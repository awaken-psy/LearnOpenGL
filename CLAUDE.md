# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This is the official code-sample repository for [learnopengl.com](https://learnopengl.com). Every tutorial demo from the book is a standalone executable, built via CMake. The code targets **OpenGL 4.5** (compatibility profile), loaded through GLAD.

## Build & run

**推荐使用 `dev.sh` 脚本（一键 configure / build / run / list）：**

```bash
./dev.sh configure                           # 初次配置 CMake（自动检测 GLM 路径）
./dev.sh build 1.getting_started__1.1.hello_window   # 编译单个 demo
./dev.sh run   1.getting_started 1.1.hello_window    # 编译 + 运行
./dev.sh list                                        # 列出所有可编译的 demo
./dev.sh build                                       # 编译全部
```

**手动 CMake 方式：**

```bash
# Out-of-source build (all platforms)
# CMake ≥ 4.0 requires -DCMAKE_POLICY_VERSION_MINIMUM=3.5
cmake -S . -B build -DCMAKE_POLICY_VERSION_MINIMUM=3.5
cmake --build build -j$(nproc 2>/dev/null || sysctl -n hw.logicalcpu)

# If GLM is not in a standard path, add -DGLM_ROOT_DIR=<path>
# To build a single demo: cmake --build build --target "1.getting_started__1.1.hello_window"

# The build directory must be named "build" (or a subfolder of the repo root)
# so the FileSystem relative-path logic can find resources at runtime.
```

**macOS** — install deps first:
```bash
brew install cmake assimp glm glfw freetype
```

**Windows** — pre-compiled libs and DLLs ship in `/libs` and `/dlls`. The CMake script auto-discovers them via custom Find modules in `cmake/modules/`. If you get link errors, the shipped binaries may be built for a different MSVC toolchain — rebuild them from source.

**Runtime resource path:** each demo's executable lands under `bin/<chapter>/`. If a demo can't find shaders/textures, set `LOGL_ROOT_PATH` to the repo root and run from there, or run the executable from `bin/<chapter>/<Debug|Release>/` so the `../../../` fallback resolves correctly.

## Architecture

### Source layout

Every tutorial is a self-contained directory under `src/<chapter>/<demo>/` containing one `.cpp` main file plus optional `.vs` / `.fs` / `.gs` / `.tcs` / `.tes` / `.cs` shader files. There are no `.h` headers per demo — shared code lives exclusively in `includes/learnopengl/`.

```
src/
  1.getting_started/     # Chapters 1-7 (window → camera)
  2.lighting/            # Colors, Phong lighting, materials, light casters, multiple lights
  3.model_loading/       # Assimp model import
  4.advanced_opengl/     # Depth/stencil/blending, framebuffers, cubemaps, instancing, anti-aliasing, UBO, geometry shaders
  5.advanced_lighting/   # Shadow mapping (directional + point), normal/parallax mapping, HDR, bloom, deferred shading, SSAO
  6.pbr/                 # PBR lighting + image-based lighting (irradiance + specular IBL)
  7.in_practice/         # Debugging, text rendering
  8.guest/               # Community articles: OIT, skeletal animation, scene graph, CSM, tessellation, DSA, compute shaders, area lights, PBR bloom
```

### Shared includes (`includes/learnopengl/`)

These are the reusable classes that demos depend on. Do not modify them without checking all consumers:

| Header | Purpose |
|--------|---------|
| `shader_s.h` | Minimal Shader (no GLM) — early Getting Started demos |
| `shader_m.h` | Full-featured Shader with `set*` uniform helpers — the most commonly used variant |
| `shader.h` | Shader variant used by mesh/model-loading tutorials |
| `shader_c.h` | Compute shader class |
| `shader_t.h` | Shader with geometry/tessellation shader support |
| `camera.h` | FPS-style Camera class (Euler angles, mouse/keyboard input) |
| `mesh.h` | Mesh struct (Vertex, Texture), `using namespace std` — used by model loading |
| `model.h` | Assimp-based Model loader |
| `model_animation.h` | Animated model support (bones, skeletal animation) |
| `filesystem.h` | `FileSystem::getPath()` — resolves resource paths using `LOGL_ROOT_PATH` env var or `../../../` fallback |
| `animator.h` / `animation.h` / `animdata.h` / `bone.h` | Skeletal animation system (guest article) |
| `entity.h` | Scene-graph entity (guest article) |

### Static libraries

Two source files are compiled as static libs and linked into EVERY demo (see CMake `add_library` calls):
- `src/glad.c` — OpenGL 4.5 loader (generated by glad)
- `src/stb_image.cpp` — STB image loader

### CMake structure

Each demo is turned into an executable by `create_project_from_sources(chapter, demo)` which:
1. Globs `.h`, `.cpp`, `.vs`, `.fs`, `.gs`, `.tcs`, `.tes`, `.cs` from the demo directory
2. Creates one executable per demo (named `chapter__demo`)
3. Copies shader files + DLLs to the output directory as a pre-build step
4. On MSVC, generates a `.vcxproj.user` for correct debugger working directory

The chapter/demo registration is in `CMakeLists.txt`: chapters in `CHAPTERS`, demo names per chapter in `set(<chapter> ...)`, guest articles in `GUEST_ARTICLES`. To add a new demo, add it to the appropriate `set(...)` list.

### Demos follow a consistent pattern

Every `main()` follows the same structure:
1. GLFW init + window creation (800×600, OpenGL 3.3 Core)
2. GLAD load
3. Configure global OpenGL state (depth test, blending, etc.)
4. Create shader program using `Shader` class
5. Set up vertex data (VAO/VBO/EBO)
6. Load textures via `stb_image` / `FileSystem::getPath()`
7. Render loop: process input → clear → bind + draw → swap buffers
8. Cleanup

Code uses `// ----` comment separators for logical sections and verbose inline comments matching the tutorial style.

## Dependencies

- **GLAD** (OpenGL 4.5 loader, vendored at `src/glad.c`)
- **GLFW 3** (windowing / input)
- **GLM** (math library, includes at `includes/`)
- **Assimp** (model import, from chapter 3 onward)
- **FreeType** (text rendering, ch. 7 + text rendering demo)
- **IrrKlang** (audio, Windows-only, breakout game)
- **stb_image** (image loading, vendored at `src/stb_image.cpp`)

Third-party headers are vendored under `includes/` (GL, GLFW, KHR, Assimp, FreeType, SOIL).
